# Changelog

Per-version notes. Test results and logs for each release live in Git history and tags.

## v108.7

- Inspector: fog `density` was listed twice in `propertyPolicy.lua`, so it appeared as two rows; the duplicate is gone. Test: `v108_7/inspector.lua` (no repeated key in the policy list).
- Shadows: black dots on smooth hills (multiplayerCars) came from using the interpolated shading normal for the slope bias and normal offset; near the terminator it disagrees with the faceted surface stored in the depth map. `world.glsl` now derives the facet normal from `dFdx/dFdy(worldPosition)` (oriented to the shading normal) and passes it to the shadow functions; lighting still uses the shading normal. Verified at Medium, High and default quality.
- Window: the UI follows a window resize while it is being dragged. `Platform:onLiveResize` installs an SDL event watch, because on Windows and macOS the modal resize loop blocks the frame loop and the UI kept the old size until release. Sandbox check `--test-v108.7.resize` (the UI matches the window two frames after a resize); the modal-loop behaviour itself needs confirmation on Windows.
- Performance: the 3D Physics debug view cost ~28 ms/frame of Lua on the `physics` scene (23 bodies) and now ~2 ms. Every wireframe edge allocated four tables (two `camera:project` points, `G.line` varargs and per-segment normals) and projected each triangle corner twice. The callbacks reuse scratch points and project each corner once; new `graphics.segment` draws a two-point line without temporaries and `graphics.line(x1, y1, x2, y2)` routes to it, which also speeds gizmos, 2D debug and charts. Probe: `--test-v108.7.debug`.
- Explorer: the category folders (Geometry, Lights, Cameras, Billboards, Physics, Effects, Audio, Scripts) are gone. Nodes sit directly under their World, exactly as the scene composes them (`world.folders.X` remains as an alias of the world root so old code keeps working). Under every World3D / World2D the Explorer lists the Environment first, then nested World2D nodes, then the remaining nodes in authored order; only the view is ordered, `children` is untouched. Test: `v108_7/explorerOrder.lua`; probe `--test-v108.7.tree` prints the rows of a scene.
- multiplayerCars: the arena is built from one list of pieces (`arenaView.statics`) instead of separate mesh and body loops. The Explorer shows `Arena (Node3D)` with every static piece as a `Body3D` that owns its visible `Mesh3D` (`Wall1 > Wall1Visual`), where it used to list `GarageColumn5`, `GroundBody` ... as two unrelated flat sets. `ArenaView.buildPhysics` still builds bodies only (tests, headless).
- Ramp goals: the goal editor now shows absolute `Start` and `Destination` values for every component, taken from the goal's own timeline (first and last point), instead of one destination plus an implicit start read from the target. The timeline editor puts its graph in a vertical `ScrollFrame`: value ranges beyond 0..1 (for example -50..140) make the graph taller (one viewport per 40 units, up to 8), keep a round value grid with labels and let the author scroll to and drag points that are outside the window; the axis range is frozen while a point is dragged. The end points have padding so they stay clear of the edge and the scroll bar. Tests: `v108_7/curveRange.lua`; probe `--test-v108.7.ramp` (screenshots and a drag through the ScrollFrame).

## v108.6

- Beam3D and Trail3D (`nodes/effects`, `source/engine/ribbons`): textured ribbons between two nodes and behind a moving node, with the common image configuration (`texture`, `imageMode`, `pixelate`, tiles, atlas, XML), `textureMode` Stretch / Wrap / Static, a `RibbonRamp` (color, transparency, width), `lightEmission`, `lightInfluence`, `castShadow` / `receiveShadow`, layer groups and shader layers. Trail3D has Single mode (one node, faces the camera) and Dual mode (two nodes mark the edges); ribbon ends accept any Node3D, so no Attachment3D is needed. New scene `ribbonLab`, guide `docs/guides/rendering/ribbons.md`, quality profiles scale ribbon detail (`ribbons.detail`).
- Shared components `components/layering.lua` (`Layering.sees(camera, node)`: the single camera/layer-group visibility test used by meshes, decals, billboards, lights, particles, ribbons and picking) and `components/renderRange.lua` (`maxDistance` normalize / describe / `within`). Eight copy-pasted bit masks and four copies of the distance test are gone.
- Networking: the interpolation delay adapts to the measured snapshot jitter (floor about 1.25 snapshot periods, ceiling the `interpolationDelay` option, `adaptiveDelay = false` keeps it fixed); an entity past its newest snapshot is extrapolated for up to `maxExtrapolation` (0.06 s) instead of freezing; the Stats panel has a Network section (ping, loss, snapshots per second, newest snapshot age, jitter, delay, extrapolated entities) fed by `Client:getStats()` through `scene.netStats`; an entity definition may have `validate(object, newState, elapsed, player)` so the server drops impossible client-authoritative reports (`Server.stateRejected` signal). multiplayerCars rejects car teleports unless they land on a spawn point.
- Collision debug `poseMode` (`Environment.debug.physics.poseMode`, F4 "Debug pose", inspector): Render (default, the interpolated pose the visuals use), Solver (newest physics step, what contacts and queries see) or Both (solver shapes in magenta over the normal colours), so the one-step gap between visuals and physics can be seen instead of guessed.
- multiplayerCars: the car model hangs below the chassis centre along the car's own up axis (`game/carAxes.lua`) instead of world Y; on a slope the model used to slide off its collision box. Test: `v108_6/carAxes.lua`.
- multiplayerCars: the cars are the Duke 69 (`assets/models/duke69.glb`, converted from the FBX by `tools/import/fbxDump.c` + `fbxCarToGlb.py`, maps by `carMaps.py`): separate wheels, dentable body parts with deeper crumpling deformation, `SurfaceAppearance3D` with colour, normal, roughness and metalness maps, clear Blend glass; suspension retuned for the new size. Space (or the phone *Drift* button) is a handbrake with rear-wheel smoke and dark `Trail3D` skid marks driven by the replicated `drift` field; a flipped car rights itself instead of respawning (respawn only below the arena). Tests: `v108_6/carDrift.lua` (the v108.6 suite now takes under 3 minutes; the car tests drive with real keys, they did not before). Screenshot probe: `--test-v108.6.shots`.
- Shadows: acne (stripes on terrain at 9 filter samples, triangles and dots on lit walls at Medium) came from one rule missing in `shadowSampling.glsl`: the slope bias covered a single tap, but the 2x2 / 3x3 PCF taps are nearest-filtered and reach `h + 0.5` texels from the texel that holds the receiver, so on a slope they read deeper neighbours and shadowed the surface. The bias now grows with the kernel reach (`1.5 * (h + 0.5)` texels: 1.5 for 4 samples, 2.25 for 9; 1 sample unchanged). Verified at Medium (256 / 4 / distance 180), High (512 / 9 / 240) and the default (1024 / 1) on wall sides, wall tops and terrain.
- Workspace: destroying the selected node while the editor was open crashed `Workspace:update` (`clear` was a local of the inspector module, undefined there). The panel reset is now `Workspace:clearInspector()`, shared by `select` and `update`. Test: `v108_6/workspaceSelection.lua`.
- multiplayerCars: a replicated walker crashed with "Animation weight must be within 0..1": the network extrapolates the walk and crouch blends past the newest snapshot, so they left 0..1 and the Idle/Walk/Crouch weights went negative. `WalkerView` clamps the blends (`Math.clamp01`). Test: `v108_6/walkerBlends.lua`.
- multiplayerCars: collision hitboxes vs the drawn scene, measured per frame at 1/30, 1/60, 1/144 and random frame times (`--test-v108.6.poses`, 28 m/s). Two real causes: (1) the seated player's capsule was placed from the stale solver-pose model (`car.x`) once per frame, offset along world Y, so it trailed the car by up to one physics step (0.43 m) and ignored the tilt; `Walker:setSeat` now takes the chassis centre and up axis at the pose the car is drawn at and `Walker:placeAtSeat` teleports the capsule there each frame (render pose reset). (2) On the hosting machine the kinematic stand-in of a car another player drives followed the newest authoritative state while the model is drawn from the interpolated replica, 1-3 m behind at speed; `PhysicsCar:followDrawn` places it at the drawn pose, like the stand-ins of joined clients. Own cars were already exact. The 3D frame is never reused while physics debug is on. Test: `v108_6/carPoses.lua`.
- multiplayerCars: simulated cars are drawn at the body's own render pose (`PhysicsCar:renderPose`, the pose the collision wireframes use); the per-frame `RenderPose` sampler is removed (a frame with two physics steps drew the car a whole step behind its hitbox). Client stand-ins for other players' cars follow the drawn pose once per frame. Collision debug `Solver` is always magenta, `Render` keeps the normal colours.
- `Net.Client` option `localServer` and `client:isMirrored(id)`: a client in the server's own process reads entities whose definition has `mirror(from, to)` straight from the server (no interpolation delay) while no client has authority over them. multiplayerCars uses it for cars, so the scene has no host-specific branch any more. Measured at 22 m/s: the host's drawn car was 2.2 m behind the physics bodies (which the collision debug shows), now 0.37 m (one step, blended). Cars driven by remote clients still use network interpolation.
- 3D collision debug draw follows the interpolated render pose (`Physics:debugPoses`) instead of the newer solver pose, so fast bodies such as cars no longer drive ahead of their wireframes. Jolt draws through its mirror world (`World:debugDraw(poses)`), other backends apply the poses for the draw and restore them. 2D debug still draws the exact solver pose on purpose.
- Folder cleanup: the small rendering-support folders now live under `source/engine/graphics` (`materials/` with `material.lua`, `shaders/` with `shaderSource.lua`, `lighting/`), surface placement moved to `source/engine/world/surfaces`, and the one-line `game/ui/statistics.lua` shim is gone. Requires were rewritten by script, the packaged `nightPlayer` fixture was rebuilt. `ribbonLab` camera now looks at the stage.
- `components/tint.lua` (colour as three channels, legacy alpha folded into `transparency`, validated once) replaces the colour/transparency set-up copied in `world/objects.lua`, Decal3D and SurfaceAppearance3D; billboards use `RenderRange` and `Tint.normalizeTransparency`.
- `ribbonLab` has a control panel (`scripts/ui/interface.lua`, collapsible, touch friendly): trail width/life/max length, blade facing, beam texture mode and glow, cast/receive shadow, light influence, clear trails.
- `components/brightness.lua` (one finite non-negative rule for decals, billboards, particles, ribbons and lights), `core/tables.lua` (`copy`, `copyAuthored` replace five private deep copies), `Math.clamp` / `Math.unit` (replace private helpers in the IK two-bone solver and ScrollFrame).
- `unlit` is replaced by `lightInfluence` (0..1) on Mesh3D, Decal3D, particles and ribbons through the shared `components/lighting.lua`; meshes blend lit and flat colour in `world.glsl`. A legacy `unlit` passed at creation is converted. Shadow options and the caster proxy are shared too (`components/shadowing.lua`, `graphics/shadows/casterProxy.lua`).
- ParticleEmitter3D: `castShadow` / `receiveShadow` now have inspector hints and conditional shadow fields.

- Android template: `android/` (Gradle + SDL2 + CMake for `libSDL2/libopenal/libmain.so`, `KatsaActivity`, `prepare.py` that fetches SDL2/OpenAL Soft/LuaJIT, cross-builds per ABI and packs `assets/game.katsa`). `katsa_host.c` has an Android branch (asset copied to internal storage once, stdout/stderr forwarded to logcat). Not built with a real NDK/SDK yet.

- Version bumped to v108.5; v108.4 stays as the last known-good release before the IK plugin and the following plugin updates.
- New plugin `ik` (3D inverse kinematics; see `docs/guides/animation/ik.md`): `SkeletonModifier` base with `influence`, `priority`, `debug`; bone pose access (`IK.Skeleton`, `IK.Quat`); solvers `TwoBone` (pole, softness), `LookAt` (weighted chains, angle limit, smoothing), `Fabrik` (pole twist), `Ccd` (step and per-joint limits), `Jacobian` (damped least squares), `Spline` (Catmull-Rom, arc-length placement) and `FK` (euler Z·Y·X per bone). - multiplayerCars: creating a car view no longer stalls for 60-90 ms. Copying the lofted body vertices with `{ unpack(vertex) }` cost about 20 us per vertex; the copy now spells the fields out and the rest pose is lofted once and shared by all cars (each car still owns its dentable vertices). `--test-v108.5.cars` no longer logs the slow `car view` step. Wheel visibility is only written when it changes.
- Input: mouse moves without a capture no longer hit-test the UI once per event. A fast mouse delivers several moves per frame and each `Input:hover` costs 0.2-0.5 ms in multiplayerCars (368 UI nodes), which showed up as a 5-12 ms event phase while the cursor moved in a car. Only the newest position is resolved, once per frame (`Input:flushHover`, also before presses).
- Frame loop: an event phase longer than 30 ms logs `Slow event phase: N ms, longest part "<name>" M ms`, telling an OS/SDL stall (`pump`) from a slow handler.
- Graphics garbage: `Batch.addQuad` and the primitive `triangle` allocated a transform closure per call (thousands per frame with rounded UI corners) and `love`-style `G.draw` built an argument table per drawable. They are inlined now; the draw phase of multiplayerCars produces about 30% less garbage per frame (1208 -> 830 KiB walking, 991 -> 668 KiB in a car), which lowers the collector's periodic frame spikes (every ~16 frames in the owner's profile).
- Console panel: with the console open the frame dropped from ~105 to ~20 FPS in the owner's recordings (every lag window started right after a console export and ended when it was closed). The panel laid out all 200 log lines as one text node every frame. It now lays out only the rows inside the scroll window (plus a margin) and moves that text with the scroll offset; the scroll range still covers every line. In the sandbox the console's Screen UI cost fell from +15.4 ms to +4 ms.
- UI / 2D batch cost: `Text:_draw2D` saved the transform with `{ unpack(...) }` for every Text object every frame (14% of a multiplayerCars UI draw in the sandbox profile); it uses locals now. `sendBuiltins` allocated 3-5 `ffi.new` buffers per flush and mesh draw; they are preallocated. The 2D batch skips re-pointing its three vertex attributes while nothing else (a mesh draw, a shader change) has changed them (`Core.batchAttributesValid`). A multiplayerCars frame has ~63 batch flushes in the UI alone, so this removes about 10 GL calls and 5 allocations from each. Screenshots of `uiGallery` and `multiplayerCars` are pixel-identical before and after.
- Menu loading label: choosing a scene in the menu builds it inside the mouse handler (about 600 ms for multiplayerCars). The menu scene itself (`menu/scripts/ui/controller.lua`) now shows a "Loading <scene>..." label and starts the scene on the second frame. The engine has no loading UI; other scenes are unaffected.
- Ctrl+C: LuaJIT raises `interrupted!` inside the frame loop; `Boot.isInterrupt` now ends the run quietly with status 130 instead of showing the error screen and a traceback.
- multiplayerCars Host: the walker and the first cars were built in one frame (peak ~75 ms in the sandbox, 87-159 ms in the owner's profile). `Session:queueView` now builds one view per frame, walker first; the frame peak drops to ~53 ms. The remaining few seconds of uneven frames after Host are LuaJIT warm-up: after a scene switch (`jit.flush`) the Lua stages run ~2x slower until traces are recompiled (Cars: physics 1.6 -> 0.6 ms, Cars: server 0.8 -> 0.25 ms between the first and the later frames).
- **Choppy cars after Host - root cause (ENet packet throttle)**: the owner's console shows `Server sent 20 snapshot packets in 1.0 s` but `Client received 2-7 ... ENet loss 0%` for the first ~5 s after Host, then 20/s. ENet drops unreliable packets while its per-peer throttle is low and does not count them as loss; a frame-paced loopback (one RTT sample per frame, plus the Host hitch) pushes the throttle down and it recovers only on acknowledgements. `katsa_net.c` now calls `enet_peer_throttle_configure(peer, 5000, 2, 0)` on every connect (deceleration 0 = the throttle never drops) and exports `knet_unthrottled()`. **The native net library must be rebuilt** (`python tools/native/build.py windows|linux|...`). `katsa.net.unthrottled()` reports it; until the library is rebuilt `engine/net/channels.lua` sends snapshots and client input on the reliable channel instead of the sequenced one, so an old library gives ordered but never silently dropped state. Test: `v108_5/netThrottle.lua`.
- Net rate log: the server logs `Server sent N snapshot packets in 1 s` and the client `Client received N snapshot packets in 1 s (expected 20), ENet loss, ping` every second for the first 12 s of a connection (the client also warns whenever it receives fewer than 75% of the expected packets). Comparing the two tells whether packets are lost on the way, batched, or never sent. Reason: the owner's console shows snapshots arriving only every 200-250 ms (4-5 Hz instead of 20 Hz) for the first seconds after Host while the server ticks normally; this could not be reproduced on Linux with real pacing and the recorded frame times.
- Choppy-motion diagnostics (console export): `Net` warns `Snapshot gap: N ms ...` when two received snapshots are more than 150 ms apart (wall time, server ticks and server time between them), and `Entity N held still for N ms ...` when a moving replica waited longer than 100 ms for a newer snapshot; multiplayerCars warns `Car N jumped X m in one frame (frame N ms, server time, ping)` for a drawn car that moves more than 2.5 m between two frames. The frame time in that line tells a hitch (large) from a data problem (normal). Parked entities send nothing and are not counted as starved.
- multiplayerCars jerky cars after Host ("teleports" every ~0.5 s): on the hosting machine the drawn car is a network replica that is already interpolated per frame, but `Session:updateRenderPoses` also blended it with the physics step alpha because the server owned a body for it. The replica changed every frame while the alpha alternated (0.44 / 0.94), so the drawn step alternated between half and double (replaying the owner's frame times: 480 outlier frames in the first seconds, coefficient of variation of the step 0.5 at a steady 120 FPS). RenderPose is now applied only to cars the client's own physics world simulates (`client.bodies`); outliers drop to 22 of 971 and the step variation to 0.01-0.08 while the car moves.
- Garbage per frame (root cause of the ~4 Hz frame spikes): the owner's profile after Host shows a Lua memory sawtooth of 40-53 MB every ~0.2 s, in step with the 18-26 ms frames, i.e. ~60 MB/s of garbage (the sandbox draw pass made ~530 KB per frame, update ~45 KB). `Shader:send` rebuilt its argument table, lookup tables and flat-number groups on every call (~620 calls per frame, 206 -> 2 KB/frame); `G.push('all')`/`G.pop` allocated a snapshot per UI text node and now recycle their stack entries. Draw garbage 533 -> 251 KB per frame (-53%). Still allocating: UI text/modifier paths, `Batch.prepareDraw`, shadow depth pass, `mesh:_bindAttributes`.
- Housekeeping: removed a stray empty `i1` file from the repository root, parenthesized the `constraints.lua` alias require and cleaned a comment in `materials/blend.lua`.

## v108.4

- Rig lighting flicker root cause: with mesh culling off the front-face winding was never sent to the driver (the applied-state cache claimed it was), so `gl_FrontFacing` was intermittently inverted and double-sided meshes (the skinned rig) got negated normals, losing the sun term. `glFrontFace` is now applied for every cull mode.
- Skinned meshes derive their normal matrix in the vertex shader from the same model matrix used for positions (kept as a hardening; the flicker itself was the winding bug above).
- Shadow view debug mode (F4 > Shadow view, or `lighting.debug.shadowView = true`): paints lit surfaces green, shadowed ones red and surfaces whose shadow data was not evaluated blue, to tell shadow-map darkness from other darkness. Brightness shows the sun cascade (brightest = nearest). F4 > Normal view (`lighting.debug.normalView`) paints world normals as colour to spot flipped skinned normals.
- New plugin `uiStyler` (style sheets by class / tag / name with `$token` values, `corner` and `stroke` pseudo properties, themes switchable at runtime; see `docs/guides/ui/uiStyler.md`) and the scene `launcherShowcase` (a launcher window in dark and light themes with an icon toolbar, grouped list, action panel, status bar and a background picture).
- Pathfinding debug view: per-map cell data (free flag, height) is cached by map revision, corners are projected without per-frame tables, and runs of neighbouring free cells are drawn as one segment (about 3x fewer line calls, identical picture; segments behind the camera fall back to per-cell lines).
- multiplayerCars voice meters: a quieter packet after a loud one no longer left the meter fading to zero while the person kept talking (the old peak kept its timestamp), and speakers whose position is unknown (driving a car) now show their meter too.
- Stats export without the panel: **F6** (also *Export Stats CSV* in the F4 menu, `statistics:export(seconds)`) saves the last 30 s of the background-recorded histories.
- Quality profiles `Low` / `Medium` / `High` (`Environment:applyQualityProfile`, F4 menu): render density, MSAA and shadow resolution cap, distance, update rate, filter samples and update budget; no feature is removed. `renderDensity` is the render-resolution scale.
- `Environment.rendering.vsync` (boolean) drives the window's vertical sync from the scene (default: the current window setting).
- `TextLabel`, `Button` and `TextBox` have a `font` property: a path resolved like image paths (`shared://fonts/test-font`, extension optional, `.ttf`/`.otf`). A missing file logs a warning and falls back to the default font. `assets/fonts/test-font.ttf` ships as an example.
- Renamed `nodes/physics/3d/constraints.lua` to `constraints3D.lua` (matching `constraints2D.lua`; the old name remains a one-line alias). The character texture `surfaces/grass.jpg` is now `surfaces/deltarune.jpg` (manifest key `deltarune`), and `surfaces/grass.png` is a real grass texture.

- Fewer hitches and faster loads: glTF accessors are read with typed arrays instead of per-number string unpacking, the multiplayerCars character is imported while the scene loads (cached for every walker), relative requires inside functions were reverted to absolute names (they cost a stack inspection per call), and the load phases of multiplayerCars show in the profiler. Steps slower than 50 ms (car / character views) are logged.

The separate `pause` scene was removed.
