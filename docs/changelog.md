# Changelog

Per-version notes. Test results and logs for each release live in Git history and tags.

## v108.9

- Engine/platform: `katsa.system.openFileDialog({ title, multiple, filters })` opens the native open-file dialog (Windows common dialog, zenity/kdialog on Linux, osascript on macOS) and returns a list of paths; `katsa.dropHandler(path)` lets a scene take dropped files instead of loading them as a scene.
- levelEditor: Import opens the system file dialog and accepts any file (models are placed, images become sprites, audio/fonts/data are copied into the level's assets); files can also be dropped on the window. Create > Visual adds Billboard, Surface UI, Decal, Surface appearance, Particles and Attachment; board text is editable in the inspector and saved with the level. Fixed a crash in hover tooltips for properties without a hint text.
- levelEditor: ribbon with category tabs (Home, Create, View, Assets) and big pixel-icon buttons; hover descriptions for ribbon buttons, fields and property names (engine hint texts); icons in menus; Assets tab chooses where imports go (`scene` copies into the level's assets folder, `shared` references a project file as `shared://`) and opens the level's assets folder; the same model can now be placed, duplicated and reopened any number of times (model root names are made unique); exported packages accept `shared://`/`scene://` model URLs.
- levelEditor: pixel-art icons (drawn in code) on the toolbar and in the Workspace tree, status-bar hints for toolbar buttons, grid cell/major/size fields in the toolbar (saved in the preferences), shorter class labels in the tree.
- levelEditor: Save/Open lost every vector property (position, size, colour, rotation, scale) because engine vectors were dropped as unsupported values; they are now written as arrays. Derived runtime statistics are no longer saved.
- Engine: light selection no longer depends on the world clock, so lights added or moved in a paused world (timeScale 0) are lit and shadowed (`world/lights.lua`).
- levelEditor: shadows on by default; three coloured point lights in the starter level; colour wheel picker for colour properties; option properties open a scrolling, searchable list instead of cycling on click.
- `levelEditor`: removed the Play button and F5 (a run changed the scene and rebuilding it afterwards turned a sphere into a cube); the editor is always in edit mode. Light markers are always drawn; a point light always shows its radius and, when selected, its range as well, spot lights and the sun show their reach when selected. Fixed the light marker crash (`worldPosition` is an empty cache before the first render) and drag-and-drop reordering in the tree.
- New scene `levelEditor` (stage a of the level editor, built only from the public engine API; nothing under `source/` changed): fly camera, ground grid, click selection with an outline, focus and frame-all, status bar. **Every control is an InputMap action** declared in the scene's `settings.input` (`editorLook`, `editorForward`, `editorPick`, `editorUndo`, ...), so each key can be rebound in the shared map. Pure parts that later stages build on, tested without a window: a stored ZIP writer (read back by the engine's `archive.lua`), the `.katsa` location data format with a version check, snap and gizmo drag math, an undo/redo stack with merge keys and transactions, a selection set. Guide: `docs/guides/development/levelEditor.md`. Stage b adds the Workspace tree (select, Ctrl/Shift multi-select, expand, show/hide, lock) and the Properties panel built from the engine's inspector rows (multi-selection edits the shared rows), with undoable create/delete/duplicate/group/ungroup/reparent/rename/copy/paste and property edits. Stage c adds Move/Rotate/Scale gizmos (world/local space, centre/origin pivot, snapping with Ctrl to invert, one undo step per drag). Stage d adds the bottom browser: a Create tab (Cube, Sphere, Plane, Capsule, Cylinder, Cone, Point/Spot/Sun lights, Empty, Camera, Spawn point, Trigger and Collider volumes as Body3D + Collider3D, Billboard) that places objects in front of the camera, and a Files tab that browses the virtual file system, imports models and images into `editor/assets/` and places them (model, sprite quad, or colour map of the selected mesh through `SurfaceAppearance3D`). Cylinder and cone are scene-built meshes (the engine has no such `kind`). Stage e adds `.katsa` export and import: Ctrl+S / Ctrl+O, a Location tab (recent files, autosave, saved locations), autosave every 60 s, and a self-contained package loader so an exported location runs as a scene. Interface pass: Godot-style docks with draggable splitters and wrapping toolbar/palette (nothing leaves the screen), editable Snap steps for move/rotate/scale in the toolbar, drag-and-drop reordering and reparenting in the Workspace, gizmos and the selection outline drawn on top of all objects, a Settings window (theme through the uiStyler plugin, dock sizes, snap and grid, camera, rebinding of every editor action) saved to `editor/settings.lua`. The 3D view now lives in a ViewportFrame between the docks (own World3D and camera; picking and gizmo drags use viewport coordinates). A menu bar (File with Save as / Import / Export, Edit, Create, View, Settings), collapsible property categories, the class name beside each Workspace row, rectangle selection, Select all, Surface snap, Play-test and view toggles (shadows, gizmos, wireframe). Tests: `v108_9/levelEditorLogic.lua` (ran in plain Lua 5.4: LuaJIT is not available in the authoring sandbox), `v108_9/levelEditorScene.lua` (not run yet: needs the engine host on the owner's machine).
- levelEditor: light icons keep a constant on-screen size so they stay visible at any distance.
- levelEditor, second observation round: every selected object now has its own outline; the highlight of a menu title no longer sticks after the menu closes (the style was not re-applied after the tag was removed); the bottom Create tab is gone, objects are created from `Shift+A` (action `editorCreate`), a **+** button in the Workspace or the Create menu, in one searchable list; the Workspace polls the pointer so click, drag-to-move and drag-over-rows selection work together; right-click context menus for viewport objects, empty space, Workspace rows, files and locations through one shared pop-up. Tests: pure range slicing in `levelEditorLogic.lua`, outlines and menus in `levelEditorScene.lua` (scene part not run yet).
- levelEditor: light visualisation (a pickable tinted marker per light, reach shapes for the selected light) replaces the engine's line gizmos; the transform tool no longer fails on nodes without rotation or size (lights); outlines skip lights and nodes without a transform.
- levelEditor: Level files tab (browse, create folder or file, rename, delete the files of the open level; imports reveal their new location); the old Files tab is now Import. Performance: outlines, gizmo and light markers no longer rewrite node properties every frame (a 30 s stats log showed 10 ms updates jumping to 63 ms while something was selected, with draw at 7 ms).
- levelEditor: file handling redone. One **Assets** tab: *Level files* (the level's own folder: Import..., New folder/file, Rename, Delete, Add to level) and *Project assets* (read-only, used in place through shared:// or copied into the level). Import (button, menu, drop) only copies into the level folder on screen and reveals the file, it places nothing; the Scene/Shared switch is gone.
- levelEditor: touch support. One pointer for mouse and finger (a finger is the left button, a long press is a right click) feeds every panel and the viewport; on-screen controls (move stick, look stick, Up, Down, Fast) fly the camera; Settings > Touch lets you choose when they show, set the look speed and **Edit layout** (drag to move, Smaller/Larger to resize, saved with the preferences). Assets footer reduced to Import / New / Add to level, with New and Rename/Delete also on right-click.
- levelEditor: files picked in the system dialog (absolute paths) now import (the virtual file system could not read them); two-finger zone select on touch screens.
- levelEditor: View > Performance info (per-part editor frame times in the status bar); hover hit-testing of tooltips and ribbon hints no longer runs every frame.
- Fixed: fullscreen could leave a black picture in scenes that reuse their last frame (the menu) and, after re-entering fullscreen, an invisible mouse cursor. A resize now schedules four redraws, because the desktop compositor can discard the old contents more than once while a window changes mode, and `setFullscreen` sets the cursor image and its visibility again, since Windows drops both on a mode change. Test: `v108_9/fullscreen.lua` (`--test-v108.9`). The Windows behaviour itself needs the owner's confirmation.
- The **F4 key** now takes the same path as the Debug button: with ImGui attached it opens the ImGui Debug window (`scene:consume('toggleDebug')`), and only without ImGui the legacy menu (`game/devtools/overlay.lua`). levelEditor: when the Dear ImGui library did not load it says why in the status bar, and its per-section editor timings (View > Performance info) are also engine profiler stages named `Editor: <section>` while the profiler records. Test: `v108_9/levelEditorLogic.lua`.
- levelEditor: **Cut, Copy, Paste, Clone** everywhere. Objects: Edit menu, the Workspace/viewport menus (Cut = copy + delete, one undo step; `Paste into` puts the clipboard inside the clicked object; Clone is the old Duplicate) and Ctrl+X (`editorCut`, rebindable). Level files: right-click a file or folder for Cut / Copy / Paste (into a folder, or next to a file) / Clone (`name_2`) / Move to... / Rename / Delete, **drag a row onto a folder row or `..` to move it**, and Paste in the New menu. `LevelFiles.copy` / `move` never overwrite and never put a folder into itself. File > **New (example level)** builds a small default level (ground, shapes, sun, lamp); the empty level is File > New empty location. Test: `v108_9/levelEditorLogic.lua`.
- ImGui on Windows: `build/buildNative.py` failed in the CI MSYS2 shell (`platform.system()` is `MINGW64_NT-...`, not `Windows`), so `cimgui.dll` was never built and the engine silently fell back to the legacy Debug/Stats/Console UI. Fixed; the `imgui` workflow now also commits the built libraries (`win-x64/cimgui.dll`, `android-*/libcimgui.so`) into `source/plugins/imgui/native/`, which the packager ships. Without the library a scene that wants ImGui now says so (levelEditor: status bar).

## v108.8

- Fixed: the Esc pause menu left the mouse captured in scenes that keep time running (`multiplayerCars`): the cursor stayed locked and hidden, so the menu could not be clicked. An open pause menu now counts as open UI (`capturesInput`). I could not reproduce a hard freeze in the sandbox, so this needs the owner's confirmation on Windows.
- Fixed: switching to fullscreen (or any window resize) cropped the picture and left the UI at the old size in scenes that reuse their last frame, such as the menu. The GL viewport was only re-applied after a present, so the first frame at the new size was drawn into the old rectangle and then reused. `katsa.resize` now calls `katsa.graphics.refreshViewport()`. Test: `v108_8/windowResize.lua`. Windows-only behaviour still needs the owner's confirmation.
- Fixed: `multiplayerCars` had no ground collision. The 7200-triangle terrain exceeded the default `maxTriangles` of the Points collider, and indexed Trimesh points were unrolled into a soup and welded again (minutes of load time). The scene sets `maxTriangles` and an indexed Trimesh now goes to the body as a mesh unchanged. `NavMap3D` also reads `navFloor`/`navWalkable` through the Collider3D's body again, so the car park deck is a second floor.
- Fixed: nodes cloned from a prefab lost `Body3D.rotationFactor` (it was missing from the inspector property list the clone copies), so the `replicationLab` player could be spun over by a collision and walk upside down. Test: `v108_8/bodyFixes.lua`.

- `voxelWorld` meshing: greedy meshing (about a third fewer rectangles on rolling terrain, far more on flat ground), per-corner ambient occlusion, 16-high mesh sections culled separately and pixelated block textures. The occlusion shade and the tile repeat travel in the vertex normal's length and the packed UVs and are decoded by `assets/shaders/voxel.glsl`.

- Fixed: the `viewLayers` pass (stareShooter outline) drifted away from the object while a following camera moved, because the pass recomputed the camera matrices the main pass had already used; it now shares them unchanged.
- Fixed in `voxelWorld`: chunks were re-meshed over and over (a chunk counted as meshed only after its upload, so the same chunk was requested again every frame), which flooded the upload queue, grew memory and showed stale meshes (ghost faces of removed blocks, invisible placed blocks). A mesh request now carries a sequence number, a chunk waiting for upload is not requested again and stale answers are dropped. The block picker (E) now closes on the second press.

- New example scene `voxelWorld`: a creative-mode block world. Chunks of 16x16x64 blocks stream around the player and are generated and meshed on `Actor` workers; only faces next to air or see-through blocks are drawn. Walk, jump, fly, break, place and pick blocks, nine-slot hotbar with a block picker, 14 generated 16x16 block tiles in one tile sheet (`tools/assets/generateBlockAtlas.py`). Test: `v108_8/voxelWorld.lua`. Guide: `docs/guides/development/actors.md`.

- **Body3D is physical data, Collider3D is collision.** The Body3D `collider` option is gone: shapes come only from `Collider3D` children (`body:addCollider{...}` creates one and applies it at once; `body:getCollider()` returns the first). `canCollide`, `canQuery`, `isTrigger` and `collisionGroup` moved from Body3D to Collider3D (Body3D keeps type, mass, density, friction, restitution, gravity scale, damping, sleeping, velocity); the body takes the combined result of its enabled colliders (collides, is queried or triggers when any does; the first enabled collider names the group), and creating a Body3D with one of those properties is an error. A Body3D with no `Collider3D` child still collides as a box of its `size` but writes a warning to the console. Physics bodies (`physics:addBody`, `other.canCollide` in ray filters) are unchanged. Every scene, the ragdoll rig, the importer's automatic collision and the lifecycle fixture were converted. Tests: `v108_8/*`, full `--test`.
- Properties window: an edited **tags** row snapped back to the old text (the row was read from the stale list instead of the node), and after a change that shows or hides other rows (a Body3D type switch hides mass, density, damping) the list waited for re-selecting the node because its structure check never expired. Rows now read tags live and a successful edit re-checks the structure on the next frame. Test: `v108_8/imguiEditor.lua`.
- **Shader2D `viewLayers`** (Godot-style `cull_mask` for 2D shaders): a list of layer groups; with `hint_layer_texture` / `hint_layer_depth_texture` the shader sees a render of only those groups, made by a second renderer at half density (shared by shaders with the same groups, no sky/gizmos/post/UI, shared shadow atlas). stareShooter: F9 outlines the character. The game runtime now also hands its renderer to the interface, so the depth and velocity hints work there. Guide: `rendering/shaders.md`. Test: `v108_8/layerPass.lua`.
- Properties: the **tags** row is a button per tag (click removes it) plus an input that adds the typed tags on Enter and clears itself; the old single text field looked unchanged after Enter, so it seemed to do nothing.
- Properties: read-only vectors (`velocity`, `angularVelocity`) show their numbers instead of a table address.
- Fixed the ImGui toolbar **Menu** button freezing the engine: it switched scenes in the middle of the ImGui frame (the context was destroyed between `NewFrame` and `Render`). Such actions now go through `host:defer(fn)` and run after the frame is drawn. Test: `v108_8/imguiEditor.lua`.

- Ragdoll (stareShooter): the floor of the scene had friction 0, so the combined friction of any body on it was 0 and a ragdoll that fell while running slid for 15+ seconds; the floor grips now (0.8) and the ragdoll stops within about two seconds. The ragdoll gets **hand and foot segments** (optional: a rig without those bones still works), because the foot and hand meshes hung beyond the shin and forearm capsules and sank into the floor, and every segment's collider is a regular **`Collider3D` child** of its body instead of the body's inline `collider` table (the ragdoll no longer passes one; the body gets its shape from the `Collider3D` child). Jolt keeps a 2 cm penetration slop, so capsules still rest about 2 cm into the floor. Probe: `--test-v108.8.ragdoll` (hips speed and lowest capsule point per second); test: `v108_8/ragdoll.lua`.
- Scene menus redone: the ImGui control panels of a scene are one window, **Controls**, with a collapsing section per panel (no header when there is a single panel; a panel with nothing to show adds nothing, and the window is as tall as its content). A Label right above a Slider names it (the slider shows its own value), buttons that share a row in the engine layout share a row (a button is as wide as its engine column), and buttons whose text ends in `: ON` / `: OFF` are checkboxes. particles: the four actions (Inspect, Burst, Clear, Reset) are one row, the toggles are checkboxes, Space and Blend share a row and the selected emitter tab is bracketed. Rows never cut a text (a crowded group wraps into fewer columns, at most four per row), `: on` / `: off` in any case is a checkbox, and `Collapsible.create(..., { demo = true })` keeps a scene's demonstration content (uiGallery) as engine UI instead of mirroring it. All 31 scenes with panels were checked by screenshot. New `ig.setNextWindowConstraints` and `ig.textWidth`. Test: `v108_8/imguiEditor.lua`.
- ImGui ignores the mouse while the game holds the cursor (relative mouse mode, e.g. first-person look in stareShooter): the virtual cursor no longer hovers or clicks windows, the wheel is not taken, and ImGui's pointer is moved away and its buttons released the frame the cursor is captured (`backend/input.lua` `locked`/`sync`). Touch is unaffected. Test: `v108_8/imguiEditor.lua`.
- UI classes: `UINode` is now only layout (position, size, anchor point), `enabled` and `layerGroup`; `Frame` adds what is drawn (`visible`, background, `interactable`, `drawSelf`) and every visual class still extends it. `Shader2D` and the `UICorner`/`UIStroke` modifiers have no `visible`, background or `interactable` any more (`Shader2D` is switched with `enabled`, like `Shader3D`). Code that reads `visible` of an arbitrary UI node treats a missing value as visible. Test: `v108_8/noOpProperties.lua`.
- The debug and editor UI is a removable module, not part of the runtime. New engine-neutral `source/engine/scenes/modules.lua` (`Modules.install`, and `scene:module(name)`, `scene:emit(hook, ...)`, `scene:consume(hook, ...)` on both runtimes) and the module list `game/runtime/modules.lua`. The Game runtime no longer contains `attachImGui`, `inspect`, `openEditor`, `toggleEditor`, `adoptControlPanel`, `syncLegacyNavigation`, `setNavigationVisible`, `buildMaterials`, the Debug button, console, Stats panel, Workspace, header, Tools panel or mixer: they live in `game/devtools/` as three modules, `overlay` (Stats, Console, Debug menu: F1/F3/F4/F6), `navigation` (legacy header, Tools panel, mixer, demo shader effects) and `editor` (ImGui host, Workspace fallback, F2, `inspect`/`openEditor`/`toggleEditor`/`adoptControlPanel` as module methods). The standalone `Host` lost its built-in Stats and Console too (the `overlay` module adds them through `options.modules`; a Host created without modules is pure engine). Scenes reach the editor only through `local editor = scene:module('editor'); if editor then editor:inspect(node) end`; input that used to read `scene.workspace`/`scene.debugOverlay` asks the hooks `blocksInput` and `capturesInput`, and first-person scenes emit `immersion(captured)` instead of calling `setNavigationVisible`. `ui/widgets/collapsible` and `Workspace` emit `controlPanel` and `editorToggled`. To build without the tools, delete the entries in `game/runtime/modules.lua` (and the folder): scenes, tests that do not use the tools and the engine keep working. Test: `v108_8/sceneModules.lua` (a scene without modules loads, runs and takes debug keys; nothing outside the list requires `game.devtools`).
- ImGui property dialogs: the sequence (Ramp points and goal tracks: an interactive curve graph with draggable points and Bezier handles, numeric time/value fields, add/delete, interpolation), goals (add/remove animated properties), gradient (colour stops), shader uniforms (hint_range, source_color, hint_enum, bool, texture paths), bone mask, plain value tables, Interaction groups (layers, 3D and 2D collisions) and Shader layers (list or table matrix, priority) editors are ImGui windows (`plugins/imgui/editors/`, opened with `host:openDialog(name, request)`; `Editors.forField` maps a property field to its dialog; `scene:openEditor('groups' | 'shaderLayers')`). The Explorer's Groups and Shaders buttons and the Properties window use them, so the editor no longer needs the legacy Workspace popups when ImGui is present (they remain as the fallback). New `ig` wrappers: `canvas()` (draw list), `radio`, `cursorScreen`, `mouse`, `mouseDown`, `invisibleButton`, `itemActive`. Test: `v108_8/imguiEditor.lua`.
- ImGui scene menus: the **Scene tools** window and its F9 key are removed (the old Tools panel is gone). Control panels of the example scenes are ImGui windows: `ui/widgets/collapsible` now registers its panel in `scene.controlPanels`, and with ImGui the panel and its toggle are hidden and `plugins/imgui/controlPanels.lua` draws a window that mirrors the panel's Buttons (same `press` handlers), Sliders (`changed`), TextBoxes and Labels; `Collapsible.adopt(scene, title, panelOrNodes, onAdopt)` does the same for panels and loose buttons that had no toggle (navMeshLab, ikLab, shapeKeysLab, starterGame, stareShooter LOD and Ragdoll, actorLab, animationTreeLab, shaderLab, particles, combined). Scenes open the editor through `scene:inspect(node)` (ImGui Explorer + Properties, legacy Workspace without ImGui) and F2 toggles those windows. Without the native library nothing changes. Not moved: scene HUDs, the multiplayerCars chat and player list, the nodeCatalog browser, UI galleries and viewport overlays (they are the demo content, not controls). Test: `v108_8/imguiEditor.lua`.
- ImGui main UI: the top bar is an ImGui toolbar (`plugins/imgui/toolbar.lua`: Menu, Pause, Stats, Scene tools, Debug, Explorer, Properties; shown while `scene.navigationVisible` is not false, so `presentation.navigation = false` and `setNavigationVisible` still hide it) and the old Navigation header, Debug button and WS tab stay hidden when the library is present. **Explorer** and **Properties** are separate, freely movable ImGui windows (`tools/explorer.lua`, `tools/properties.lua`): the tree is searchable, folds and draws only the visible rows; Properties groups fields like the old inspector and edits through the shared `Properties.set` (checkboxes, drags with typed input, combos, colour pickers, node pickers, text applied on focus loss, attributes, read-only reasons and hints as tooltips, the interactable blocker). Sequence, bindings and gradient fields, Groups and Shaders still open the engine's own dialogs. Shared pieces moved out of the legacy panel: `Workspace:treeRoots`, `Properties.read`, `Inspector.group`, `NodeChoices.list`. The legacy Workspace panel remains as the fallback without the native library. New `ig` wrappers: `pushColor/popColor`, `smallButton`, `tooltip`, `hovered`, `deactivatedAfterEdit`, `beginCombo/endCombo`, `available`, `dummy`, `lineHeight`, `setCursorX`. Test: `v108_8/imguiEditor.lua`.
- Fixed a freeze/crash when a larger ImGui window opened (Debug F4 in stareShooter and replicationLab): ImGui regrows its draw mesh, `Core.deleteResources` deleted the old index buffer but `Core.boundElementBuffer` still named it, so a new buffer that reused the id was never bound and the next draw read address 0 (a segfault in llvmpipe, a hang on real drivers). Deleting buffers now clears the cache. Tests: `v108_8/graphicsCache.lua`, `imguiTools.lua`.
- ImGui tools: **Debug** (F4: tabs 2D Physics, 3D Physics, Rendering, Directions, Diagnostics with every switch and slider of the old Debug menu, live values), **Profiler** (stage table with share bars, frame graph, loading phases, session recording and JSON/CSV export, error journal) and **Console** (F1: level and text filters, colours, follow-the-tail, JSON/CSV export, Clear) are ImGui windows now; the Debug button opens the ImGui window, and without the native library the old overlay, diagnostics popup and console remain. New `ig` wrappers: `plotHistogram`, tabs (`beginTabBar`/`beginTabItem`), `scrollY/scrollMaxY/scrollToEnd`. Workspace and Inspector stay on the engine UI. Test: `v108_8/imguiTools.lua`.
- ImGui: the backend loads DejaVu Sans (`assets/fonts/engine`, `options.font` overrides it) instead of ImGui's built-in Latin-only font, so Cyrillic and other non-Latin text typed into a Stats filter or any ImGui field is drawn instead of `?`. The `tagDepth` property of `Shader2D`/`Shader3D` is removed: how far a `#shader-` tag reaches is set only by the node attributes `shaderDepth.<group>` / `noShaderDepth.<group>`. Test: `v108_8/imgui.lua`.
- Datamosh (stareShooter) now moves pixels like a real one: one motion vector per block (`blockSize`), the old pixels are pushed along it in whole pixels (`drag`, at least `push` pixels where anything moves, `meshBoost` extra on moving objects), so edges tear and colours smear instead of blurring; `pin` holds the frame on screen as the reference. Test: `v108_8/effectHistory.lua` (a pinned frame differs from the live render after a camera pan).
- Inspector: the `replicatedProperties` row now appears (and the list rebuilds) when `replicated` is switched on at run time; the schema signature did not include it, so the row only showed after reselecting a node that was already replicated at selection time. Test: `v108_8/replication.lua`.
- Spatial shaders get `hint_velocity_texture` too (the same lazy velocity pass; `Material.velocityUniform`, bound in `SceneTextures.bind`). Test: `v108_8/effectHistory.lua`.
- Frame history and motion vectors for `canvas_item` shaders: `hint_history_texture` (the shader's own previous result, `ui/drawing/effectHistory.lua`) and `hint_velocity_texture` (per-pixel motion of the 3D render in `rg`, 1 in `b` where a moving mesh wrote it). The velocity pass (`graphics/pipeline/velocity.lua`, shaders `velocity.glsl` and `post/velocityCamera.glsl`) is lazy: a fullscreen pass reprojects every surface point with last frame's camera, and meshes whose matrix or bone palette changed are drawn over it with their previous matrix and palette (skinned too); without a shader asking for it the cost is remembering two camera matrices. Not covered: user-shader vertex displacement, blend shapes, particles, transparent meshes. The uniform editor does not list the two hints. stareShooter's `Datamosh` is now a real datamosh (history drag along motion vectors, the live picture leaks back slowly with a soft periodic swell, no hard reset; `pin` holds the frame on screen, F8 in the demo). Tests: `v108_8/velocity.lua`, `effectHistory.lua`.
- stareShooter: a level-of-detail demo (two rows of trees, hard switch and 0.4 s fade, billboard as the last level, a slider for the maximum distance; the scene now lists the `lod` plugin) and a `Datamosh` screen shader (`assets/shaders/datamosh.glsl`, off by default, F7). Test: `v108_8/stareLod.lua`.
- LOD is now a plugin (`source/plugins/lod`, scenes opt in with `plugins = { 'lod' }`): the `LODGroup` node, the level choice, fade/shadow/billboard helpers and the `-lodN` import grouping moved out of the core. Plugin manifests gain `importers` (modules run after every model instantiation, via `Plugins.afterImport`) and `quality` (extra `Environment.render` values per quality profile); the core has no LOD code left. `Environment.render.lodBias` is no longer a core setting or inspector entry; the plugin sets it with the profiles.
- LOD extensions: model names accept `-col` and `-lodN` in any order (`Tree-lod0-col`), only level 0 has a collider (a `-col` on a coarser level is ignored with a journal warning; a hidden `-colonly` mesh is the simple collider), and `Tree` next to `Tree-lod0` is a clear error; `settings.lod.groups = { Tree = {...} }` sets one group, and levels with different parents move into the group keeping their world position. `LODGroup` gets `fadeTime` (cross-fade by transparency), `animationRates` (Animator pose rate per level), `shadowLevel`, `referenceFov` (zoom compensation in `Distance` mode) and a billboard level (`billboardImage`, `billboardWidth/Height/Pivot`). `Environment.render.lodBias` (Low 1.5, Medium 1.2, High 1) multiplies every group bias. New `lod/level.lua`, `lod/billboard.lua`, `ModelNodes.parse`, `Animator.of`. Tests: `v108_8/lodImport.lua`, `lodEffects.lua`.
- Level of detail: new `LODGroup` node shows one of its children by camera distance or by size on screen (`mode`, `distances`, `screenSizes`, `bias`, `hysteresis`, `radius`, `forceLevel`, read-only `level`), with defaults taken from the group size. Model files with nodes named `<name>`, `<name>-lod1`, `<name>-lod2` are grouped on import (`settings.lod`, `model.lodGroups`); skinned levels on one armature keep the animation. The level choice is plain functions in `source/plugins/lod/select.lua`; `autoCollision` and the LOD importer share `import/modelNodes.lua`. Guide: `docs/guides/rendering/lod.md`. Stage 1 of the migration plan: frame-synchronization fixes and Camera3D projection modes. The `katsa` platform layer starts in the next stage.

- Fixed slow-motion stutter in per-tick gameplay state. Facing and animation blend weights authored in the fixed step (Stare Shooter body turn, walk/crouch blending) are now sampled with the same interpolation alpha as bodies through the new `engine/animation/stepValue.lua`. At TimeScale 0.1 the visual yaw changes on 110 of 119 frames instead of 12.
- Fixed Camera2D lagging behind interpolated Body2D visuals. `followTarget` now follows the drawn (interpolated) pose, which removes the jitter of the Ability Runner 2D sprite inside its Body2D at high refresh rates and in slow motion.

Projection, pointer rays, picking, frustum culling, shadow receivers, billboards, world-space UI and debug gizmos support both modes. Software occlusion culling is skipped for orthographic cameras.
- Fixed skeleton animation looking like low FPS under TimeScale. `Animator.poseRate` was gated on scaled time, so a world at 0.5 posed every 2nd frame and at 0.1 every 10th. It now budgets poses per wall-clock second (`world.frameRealDelta`).

- Fixed orthographic cameras slicing the map when they approach the ground: clipping now starts behind the camera (`orthoNear`, default `-far`) instead of at a positive `near`.
